# Управление CEH CRM через удалённый MCP

## Границы доступа

Все инструменты работают от имени вошедшего пользователя CRM и обязаны сохранять ограничения его рабочей области и роли. Наличие инструмента не даёт дополнительных прав. Если API возвращает `403` или объект отсутствует в доступной рабочей области, не пытайся обходить ограничение.

## Чтение

- `crm_resolve_project` — обязательное определение проекта по номеру заказа, адресу, клиенту, телефону или названию; возвращает внутренний `project_id`.
- `crm_search` — общий поиск по CRM.
- `crm_list` — списки с фильтрами.
- `crm_get` — одна карточка по внутреннему идентификатору. Номер заказа нельзя передавать как `id`.

Ресурсы: `clients`, `projects`, `payments`, `project-comments`, `production-plans`, `measurement-sheets`, `measurement-scans`, `project-statuses`, `finance-categories`, `accounts`, `project-custom-fields`, `document-templates`, `tasks`, `task-templates`, `audit-logs`, `users`.

## Изменения

- `crm_create` — создание объекта.
- `crm_update` — частичное изменение.
- `crm_delete` — удаление.
- `crm_action` — специальное действие.
- `crm_upload_file` — загрузка исходника в поле проекта или публикация готового PDF/DXF в `Чертежи`.

Перед удалением, утверждением производственного задания, изменением платежа, счёта, пользователя, статуса или финансовой категории обязательно покажи пользователю конкретный итог операции и получи явное подтверждение. Только после этого передавай `confirm=true`. Не считай общую просьбу «управляй CRM» подтверждением отдельного удаления или финансового изменения.

Перед любой финансовой операцией сначала получи список счетов через `crm_list resource=accounts` и обязательно спроси пользователя, где проходит операция: например, «Наличные» или «Безнал». Не выбирай счёт автоматически даже тогда, когда в списке пока один счёт. «Личные доходы» и «Личные траты» записывай без проекта в категории с `affects_margin=false`: они меняют кассу выбранного счёта, но не прибыль и маржу бизнеса.

Обычное создание комментария, задачи, черновика замера или неутверждённой ревизии задания допускается по прямой просьбе пользователя без второго вопроса.

## Специальные действия

- `project_activity` — история проекта, чтение.
- `project_status_checks` — контроль статуса проекта, чтение.
- `create_yandex_folder` — создать или восстановить папку проекта на Яндекс.Диске; требует подтверждения.
- `set_yandex_public_link` — изменить доступ к папке; требует подтверждения.
- `approve_production_plan` — утвердить готовую ревизию; требует подтверждения и административной роли.

## Файлы

Передавай файл из текущего чата напрямую в параметре `file`. Для стандартного поля «Замер» при `target=project_field` `field_id` можно не указывать; для другого файлового поля укажи его идентификатор. Для `target=drawings` разрешены только финальные `.pdf` и `.dxf`; предварительно выполни размерную и визуальную проверку. Максимальный размер файла — 8 МБ.
