# Задачи и поездки

Для tasks читать и записывать `scheduled_date` (дата выполнения), `due_date` (крайний срок), `priority`, `city`, `district`, `address`. Приоритеты: `high` — срочно, близкий жёсткий срок или блокировка работ; `medium` — обычная задача; `low` — гибкая задача без срочного срока. Если срочность не следует из поручения, использовать `medium`, а не выдумывать её. Связь с проектом необязательна. Место задачи — место действия: магазин для закупки, объект для монтажа, мастерская для сборки. Для работы на объекте брать известный адрес проекта. Не копировать адрес объекта в закупку.

Из разговора выделять результат и только необходимые отдельные действия. Краткое название — глагол и предмет, в `notes` лишь существенные детали без пересказа речи. Для основной задачи получить её ID и создать отдельные подзадачи с `parent_task=<ID>`; проект и исполнитель должны совпадать с родителем. Проверять существующие задачи, не плодить дубли. Например, перед монтажом зеркал отдельно проверить размер подрезки, отвезти в стекольную мастерскую, подтвердить готовность, забрать и затем смонтировать. Адрес каждого выезда относится к месту конкретного действия. Не додумывать шаги, материалы и сроки без фактов. Основную задачу завершать после подзадач и самой работы: CRM отклонит закрытие при открытых подзадачах. Для просмотра детей использовать `crm_list` с `filters.parent_task` или поле `subtasks` карточки родителя.

Для `crm_list` tasks передавать filters `date=YYYY-MM-DD`, `city`, `district`, `status=open`, при необходимости `project`. Фильтр date использует scheduled_date, а для старых задач без неё — due_date. Не назначать дедлайн из плановой даты. Сегодня определять в Europe/Moscow.

Рабочие зоны Ростова: Западный (ЗЖМ), Северный (СЖМ), Центр, Сельмаш, Береговая. Это направления, а не административные границы. Аксай и Батайск — отдельные города. Передавать полный известный адрес в `address`: CRM сама нормализует его через DaData и заполнит недостающие `city` и `district`. Не придумывать дом или район, которых пользователь не называл. Если адрес неоднозначен, уточнить его, сохраняя известное поручение.

Группировать план сначала по дате, затем по городу и району. Две готовые задачи на Западном в один день показывать общей поездкой с двумя отдельными действиями и статусами. Разные даты не объединять; задачи не сливать и сроки не менять без поручения. Просроченное, без даты, дистанционные действия и ожидание готовности показывать отдельно. Соблюдать зависимости: сначала получить уплотнитель, затем установить. Без адресов и маршрутизации не обещать точное время дороги и оптимальный маршрут.

## Повторные поездки между днями

Перед озвучиванием плана, созданием/переносом выездного поручения и по «сегодня еду на Западный» читать незавершённые задачи на ближайшие семь дней, просроченные и без даты. Проверка только date=сегодня не видит будущие поездки. Сопоставлять город и нормализованный район, известный адрес/поставщика; звонки о будущем визите не считать поездкой. Учитывать явно указанные места в старых title/notes, не угадывать районы.

Если сегодня и в другой день есть поездки в одно направление, сразу предупреждать до перечисления плана: назвать конкретные задачи и даты, предложить перенести гибкое сегодняшнее дело на день будущей поездки либо выполнить готовое будущее дело сегодня. Проверять крайний срок, согласованную встречу, часы работы, готовность материалов и зависимости. Если эти условия неизвестны, назвать проверку и формулировать перенос условно. Не двигать фиксированные встречи как свободные и не предлагать нарушение срока. При несовместимости объяснить необходимость разных поездок.

Анализ и предупреждение обязательны без отдельной просьбы оптимизировать. Не менять даты до явного выбора пользователя. После выбора менять только scheduled_date конкретных задач, сохранять due_date, проекты и отдельные статусы; перечитать оба дня и сообщить результат. Не сливать записи и не создавать дубли. Во время озвучивания можно дать рекомендацию и продолжить список, не требуя немедленного ответа. Это поведение при обращении к навыку, не постоянный фоновый мониторинг.
